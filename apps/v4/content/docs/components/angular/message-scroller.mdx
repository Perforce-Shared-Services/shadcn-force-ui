`MessageScroller` pins the viewport to the newest message while the reader is already at the bottom, backs off when they scroll up, and anchors each turn near the leading edge instead of snapping to the document bottom.

## Usage

```ts
import {
  MessageScroller,
  MessageScrollerButton,
  MessageScrollerContent,
  MessageScrollerProvider,
  MessageScrollerViewport,
} from "@/components/ui/message-scroller"
```

```html
<div uiMessageScrollerProvider>
  <div uiMessageScroller class="h-96">
    <div uiMessageScrollerViewport ariaLabel="Conversation">
      <div uiMessageScrollerContent>
        <div uiMessageScrollerItem messageId="m-1" [scrollAnchor]="true">
          …messages…
        </div>
      </div>
    </div>
    <button uiMessageScrollerButton></button>
  </div>
</div>
```

The host must be height-constrained — `size-full` only resolves against an ancestor with a real height. `MessageScrollerProvider` publishes the scroller state to descendants via dependency injection; inject it with `injectMessageScroller()` to read `isAtStart`, `isAtEnd`, `canScrollToEnd`, `currentAnchorId`, `visibleMessageIds`, or to call `scrollToEnd()`, `scrollToStart()`, and `scrollToMessage(id)`.

## Composition

```
MessageScrollerProvider ([uiMessageScrollerProvider])   state + DI context
└── MessageScroller ([uiMessageScroller])               layout root, must be height-constrained
    ├── MessageScrollerViewport ([uiMessageScrollerViewport])     native scrolling element
    │   └── MessageScrollerContent ([uiMessageScrollerContent])  role="log" live region
    │       └── MessageScrollerItem* ([uiMessageScrollerItem])   one row per message
    └── MessageScrollerButton ([uiMessageScrollerButton])        floating jump-to-edge button
```

## Accessibility

- `MessageScrollerContent` sets `role="log"`, `aria-live="polite"`, and `aria-relevant="additions"` so new turns are announced without re-reading the transcript.
- The viewport is keyboard-operable (`tabindex="0"`) and becomes a labelled `role="region"` when you pass `ariaLabel`.
- `MessageScrollerButton` is removed from the tab order and the accessibility tree when its target edge is already visible.

## RTL

Pointer to `/docs/rtl`: the scroller honors direction via CSS logical properties (`inset-s`, `translate-x` with the `rtl:` variant) — no extra setup is required.

## API Reference

### MessageScrollerProvider

| Prop | Type | Default |
| --- | --- | --- |
| autoScroll | boolean / Input&lt;boolean&gt; | true |
| defaultScrollPosition | "start" \| "end" \| "last-anchor" | "end" |
| scrollPreviousItemPeek | number / Input&lt;number&gt; | 24 |

### MessageScrollerItem

| Prop | Type | Default |
| --- | --- | --- |
| messageId | string / Input&lt;string \| undefined&gt; | undefined |
| scrollAnchor | boolean / Input&lt;boolean&gt; | false |

### MessageScrollerViewport

| Prop | Type | Default |
| --- | --- | --- |
| ariaLabel | string / Input&lt;string&gt; | undefined |
| className | string / Input&lt;string&gt; | undefined |

`ariaLabel` turns the viewport into a labelled `role="region"`; it defaults to `"Conversation"` when unset.

### MessageScrollerButton

| Prop | Type | Default |
| --- | --- | --- |
| direction | "start" \| "end" | "end" |
| variant | ButtonVariant | "secondary" |
| size | ButtonSize | "icon-sm" |

For the full hook surface (`useMessageScroller`, `useMessageScrollerScrollable`, `useMessageScrollerVisibility`), see the upstream React API reference.

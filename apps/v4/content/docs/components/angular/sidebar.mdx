## Usage

```ts
import {
  Sidebar,
  SidebarContent,
  SidebarFooter,
  SidebarGroup,
  SidebarGroupContent,
  SidebarGroupLabel,
  SidebarHeader,
  SidebarInset,
  SidebarMenu,
  SidebarMenuButton,
  SidebarMenuItem,
  SidebarProvider,
} from "@/components/ui/sidebar"
```

```html
<div uiSidebarProvider>
  <nav uiSidebar>
    <div uiSidebarHeader></div>
    <div uiSidebarContent>
      <div uiSidebarGroup>
        <div uiSidebarGroupLabel>Application</div>
        <div uiSidebarGroupContent>
          <ul uiSidebarMenu>
            <li uiSidebarMenuItem>
              <button uiSidebarMenuButton>Calendar</button>
            </li>
          </ul>
        </div>
      </div>
    </div>
    <div uiSidebarFooter></div>
  </nav>
  <main uiSidebarInset><!-- your app content --></main>
</div>
```

Wrap the whole app-shell region in `[uiSidebarProvider]` (it owns the shared
open/collapsed/mobile state), `[uiSidebar]` on the panel itself — a `<nav>`
keeps the landmark semantics — and `[uiSidebarInset]` for the content area.

The attribute selectors keep native element semantics (Angular's idiomatic
equivalent of React's `asChild`): `SidebarMenuButton` and its sub-button are
attribute-only, so they ride a native `<button>` or `<a>`.

## API Reference

This component is a Force UI original composed from native elements and other
Force UI parts — see the base page's API reference for the part-by-part props:
each Angular part is an attribute directive/component carrying the same inputs
(`side`, `variant`, `collapsible`, `isActive`, `size`, `showOnHover`, …) as its
React prop counterpart. `SidebarProvider.open` is two-way bindable via
`[(open)]`, the Angular equivalent of React's `open` / `onOpenChange` pair.
